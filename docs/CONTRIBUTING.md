# المساهمة في مِعيار

شكرًا لاهتمامك. هذا المشروع يضع الدقة قبل السرعة، والشفافية قبل الشمول. أي مساهمة يجب أن تحافظ على هذه القيود.

---

## 1. قبل البدء

- اقرأ [SCIENTIFIC-METHODOLOGY.md](SCIENTIFIC-METHODOLOGY.md) و[DATA-SOURCES.md](DATA-SOURCES.md).
- لا تقترح درجة مركبة أو ترتيبًا للمنتجات أو تصنيفًا تجاريًا.
- لا تُضف قيمة بلا مرجع يمكن فتحه.
- لا تُضف تركيزًا مشتقًا من ترتيب INCI.
- لا تحوّل «غير معروف» إلى «آمن».

---

## 2. الإعداد

```bash
git clone <repo>
cd miyar
npm ci
npm run dev
```

المتطلبات: Node.js 20+، npm.

---

## 3. أنواع المساهمات

### 3.1 تصحيح بيانات
1. افتح الوثيقة الأصلية.
2. تحقق من القيمة أو الحالة أو رقم الوثيقة.
3. عدّل البطاقة في JSON.
4. حدّث `last_reviewed` و`verification_status`.
5. أضف/حدّث المرجع إن لزم.
6. حدّث `meta.json` إذا تغير العدد أو النطاق.
7. شغّل التحقق والاختبارات.

### 3.2 إضافة مادة جديدة
- غذائية: أضف إلى `foodAdditives` بمعرّف `FOOD-ADD-00NN`.
- تجميلية: أضف إلى `cosmeticIngredients` بمعرّف `COS-ING-00NN`.
- لا تكرر مادة موجودة تحت اسم آخر؛ حدّث `synonyms_*` بدلًا من ذلك.
- املأ الحقول الإلزامية كلها. راجع [DATABASE-SCHEMA.md](DATABASE-SCHEMA.md).
- أضف اختبارًا إن كانت المادة تمثل حالة حدية مهمة.

### 3.3 إضافة مرجع
- `id` فريد بصيغة `REF-...`.
- `document_number` حقيقي.
- `url` مباشر إلى الوثيقة أو صفحة الاعتماد الرسمية.
- `accessed` بتاريخ اليوم بصيغة `YYYY-MM-DD`.
- لا تستخدم روابط مختصرة أو صفحات بحث.

### 3.4 تعديل المحرك
- أضف اختبارًا أولًا أو مع التعديل.
- لا تُغيّر عتبات FSA NPM دون مرجع رسمي.
- لا تُضف حقل `score` لنتيجة التجميل.
- حافظ على سلوك «التحقق غير ممكن» عند غياب التركيز.
- حافظ على عدم اعتبار الماء مكوّنًا مجهولًا.

### 3.5 واجهة أو تصميم
- العربية أولًا وRTL أصلي.
- استخدم متغيرات CSS الموجودة في `src/styles/global.css`.
- لا تُضف مكتبة UI أو أيقونات دون مبرر.
- اختبر 360px و768px و1280px.
- حافظ على تباين كافٍ، وتركيز لوحة المفاتيح، و`aria-label` حيث يلزم.
- لا تُخفِ التحذيرات أو تحديات المنهجية في التصميم.

### 3.6 توثيق
- العربية هي لغة الوثائق الأساسية.
- المصطلحات التقنية تُترك بالإنجليزية بين قوسين عند الحاجة.
- لا تنسخ نصوصًا محمية بحقوق دون إذن.

---

## 4. قواعد التحرير العربي

- استخدم العربية الفصحى المعاصرة، لا ترجمة آلية.
- وحّد المصطلحات:
  - `hazard` = خطر.
  - `risk` = قابلية للخطر.
  - `ADI` = المدخول اليومي المقبول.
  - `labelling` = وسم.
  - `leave-on` = يُترك على الجلد.
  - `rinse-off` = يُشطف.
- لا تخلط «محظور» و«مقيد» و«وسم إلزامي».
- لا تكتب «آمن» أو «ضار» كحكم مطلق.
- استخدم «لا تتوفر معلومات كافية لإصدار حكم موثوق» عند الجهل.
- تجنب التوكيدات التسويقية.

## 5. الاختبارات المطلوبة

قبل أي Pull Request:

```bash
npm run validate
npm test
npx tsc -b
npm run build
```

يجب أن تنجح الأربعة. لا تُعطّل اختبارًا لتجاوز فشل؛ أصلح السبب أو وثّق لماذا الاختبار خاطئ.

### إضافة اختبار
- اختبارات الوحدات في `tests/*.test.ts`.
- استخدم `makeFoodProduct` من `tests/helpers.ts` للغذاء.
- لا تعتمد على الشبكة في الاختبارات.
- لا تعتمد على `Date.now()` أو ترتيب عشوائي.
- اختبر الحالة السلبية (نقص البيانات، تركيز غير معروف، مكوّن غير مطابق) بقدر الحالة الإيجابية.

## 6. قائمة مراجعة Pull Request

- [ ] لا توجد قيمة أو حد أو رقم وثيقة بلا مرجع.
- [ ] كل `reference_id` موجود.
- [ ] `meta.json` محدّث إذا تغيرت الأعداد.
- [ ] `last_reviewed` محدّث للبطاقات المعدلة.
- [ ] لا `TODO` أو `TBD` أو نص مؤقت.
- [ ] لا درجة مركبة أو ترتيب منتجات.
- [ ] لا استنتاج تركيز من ترتيب INCI.
- [ ] «غير معروف» لم يُحوَّل إلى «آمن».
- [ ] الاختبارات الأربعة ناجحة.
- [ ] التغيير موثق في `CHANGELOG`.
- [ ] الواجهة تعمل على الجوال وسطح المكتب.
- [ ] لا أسرار أو مفاتيح أو بيانات شخصية.

## 7. الإبلاغ عن خطأ علمي

استخدم قالبًا يوضح:
- البطاقة والمعرّف.
- القيمة الحالية.
- القيمة المقترحة.
- النص الحرفي من المصدر (أو مقتطف).
- رابط الوثيقة ورقمها وتاريخ الاطلاع.
- هل التغيير جوهري (يستلزم رفع الإصدار) أم تحريري.

لا تُقبل تصحيحات مبنية على «سمعت» أو «مدونة» أو «فيديو» فقط.

## 8. السلوك

- نقد المنهجية مرحّب به.

- لا تُستخدم المساهمات للترويج لمنتج أو علامة.
- لا تُضاف إعلانات أو روابط تابعة (affiliate).
