# البنية المعمارية — مِعيار

## 1. نظرة عامة

مِعيار تطبيق ويب أحادي الصفحة (SPA) مبني بـ React 19 وTypeScript وVite. لا يوجد خادم تطبيق ولا قاعدة بيانات شبكية: قاعدة المعرفة تُضمَّن في الحزمة كملفات JSON، والمحركان يعملان في المتصفح. هذا قرار متعمد يجعل التقييم قابلًا للفحص، ويمنع إرسال بيانات المنتج إلى طرف ثالث، ويسمح بالنشر على استضافة ثابتة مثل GitHub Pages.

```
المستخدم
  │
  ├── صفحات الإدخال (Food / Cosmetics)
  │        │
  │        ├── تطبيع وتقسيم النص (normalize.ts)
  │        ├── استيراد اختياري خام (barcode.ts)
  │        ▼
  │   محرك الغذاء                      محرك التجميل
  │   ├── NPM (npm.ts)                 ├── مطابقة INCI
  │   ├── مطابقة الإضافات (match.ts)   ├── قابلية تطبيق الحدود
  │   └── تجميع التقرير                ├── تحقق التركيز
  │        │                           └── محاور وتنبيهات
  │        ▼
  │   EvaluationResult (نوع اتحادي)
  │        │
  │        ├── AppContext → sessionStorage / localStorage
  │        └── ReportPage → عرض + طباعة/PDF
  │
  └── قاعدة المعرفة (JSON) ←→ KnowledgeBase / Sources / Methodology
```

## 2. طبقات المشروع

### 2.1 طبقة المجال (`src/types/index.ts`)
عقود TypeScript لكل شيء: المراجع، الحالات التنظيمية، الحدود، الإدخال الغذائي والتجميلي، نتائج التقييم والتنبيهات. لا تحتوي الطبقة على منطق؛ هي مصدر الحقيقة للنماذج.

### 2.2 طبقة البيانات (`src/database/`)
- `food/additives.json`: 21 إضافة غذائية.
- `cosmetics/ingredients.json`: 50 مكوّنًا تجميليًا.
- `references/references.json`: 56 مرجعًا.
- `meta.json`: النسخة، تاريخ التحديث، العدادات، النطاق، سجل التغييرات.
- `index.ts`: يحمّل JSON ويبني `referenceMap` ودوال `getReference` و`getReferences`.

قاعدة المعرفة **لا تستورد** أي منطق تقييم. المحركات تقرأ منها، وليس العكس. هذا يسمح بمراجعة البيانات دون تغيير الحساب، وباختبار البيانات بمعزل عن المحرك.

### 2.3 طبقة المكتبات (`src/lib/`)
| الملف | المسؤولية |
|---|---|
| `normalize.ts` | تطبيع NFKC، إزالة التشكيل، توحيد الألف/الياء/التاء المربوطة، تحويل الأرقام العربية، استخراج أرقام E، تقسيم قائمة المكونات مع احترام الأقواس والفواصل العشرية، مرادفات التجميل. |
| `units.ts` | تحويل kcal→kJ بمعامل 4.184، والملح↔الصوديوم (÷2.5×1000)، والتحقق من الأعداد. |
| `food/npm.ts` | عتبات FSA NPM الرسمية، حساب A وC، قاعدة استبعاد البروتين، التصنيف، صفوف العرض، القيود. |
| `food/match.ts` | بناء مرادفات كل إضافة (E، أسماء إنجليزية/عربية)، مطابقة النص المطبع، إبقاء غير المطابق. |
| `food/evaluate.ts` | اكتمال البيانات، تنبيهات NPM، ADI، تحويلات، حدود، مراجع، تجميع النتيجة. |
| `cosmetics/evaluate.ts` | تقسيم INCI، المطابقة، فحص `leave_on` و`product_types`، التحقق من الحدود، تحديد الوسم/الحظر/الجهل، العدّادات، التنبيهات. |
| `barcode.ts` | جلب حقول خام من Open Food Facts / Open Beauty Facts مع مهلة، دون أي درجة خارجية. |
| `history.ts` | سجل محلي (24 عنصرًا) ولقطات نتائج (12) في التخزين المحلي، وآخر نتيجة في `sessionStorage`. |

### 2.4 طبقة الحالة (`src/context/AppContext.tsx`)
سياق واحد يحمل:
- `result`: آخر نتيجة تقييم.
- `history`: قائمة ملخصة للسجل.
- `setResult`: يحفظ النتيجة واللقطة ويضيف للسجل.
- `openHistory(id)`: يعيد فتح لقطة محفوظة.
- `clearHistory()`: يمسح السجل واللقطات.

لا توجد مكتبة إدارة حالة خارجية؛ الحالة صغيرة ومحلية بطبيعتها.

### 2.5 طبقة الواجهة
- `components/Layout.tsx`: الهيدر، التنقل، الفوتر، تجاوز المحتوى، التمرير لأعلى عند تغيير المسار.
- `components/ui.tsx`: الشارات، عناوين الأقسام، التنبيهات، مقياس الاكتمال، الحالة الفارغة، الروابط الخارجية.
- `components/form.tsx`: حقول نصية ورقمية وقوائم ونصوص طويلة مع تسميات وصفية.
- `components/Icons.tsx`: أيقونات SVG مضمّنة (لا مكتبة أيقونات خارجية).
- `pages/*`: صفحة لكل مسار. `ReportPage` هو أكبر مكوّن، ويعرض تقرير الغذاء أو التجميل حسب `result.kind`.

### 2.6 طبقة التنسيق (`src/styles/global.css`)
نظام تصميم واحد: متغيرات CSS للألوان والخطوط والمسافات، RTL أصلي (`dir="rtl"` على `<html>`)، نقاط توقف 1024/860/640، أنماط طباعة تُخفي الهيدر والفوتر وتفكك الشبكات، ودعم `prefers-reduced-motion`.

## 3. مسار البيانات بالتفصيل

### 3.1 الغذاء
1. المستخدم يدخل القيم لكل 100 غ/مل.
2. `toNumberOrNull` يرفض غير الرقمي والسالب.
3. `evaluateFood` يستدعي `evaluateNpm`:
   - يحوّل kcal→kJ أو الملح→صوديوم عند الحاجة ويسجل ملاحظة.
   - يحسب نقاط كل عنصر عبر عتبات صارمة (`>` وليس `≥`).
   - يتحقق من اكتمال A وC والبروتين.
   - يطبق استبعاد البروتين ثم يحسب `score = A − C`.
   - يحدد التصنيف حسب نوع المنتج.
4. `matchFoodAdditives` يطابق النص مع القاعدة.
5. `evaluateFood` يبني التنبيهات (عدم كفاية، تصنيف، حظر، ADI، تحويلات، نوع ألياف، عدم مطابقة) ويجمع المراجع.
6. النتيجة تُحفظ وتُعرض.

### 3.2 التجميل
1. `splitIngredientList` يقسم النص ويستخرج نسبة نهائية إن وُجدت.
2. يُبنى فهرس مطابقة من الاسم وINCI والمرادفات بعد التطبيع.
3. لكل مكوّن:
   - مطابقة تامة، ثم مطابقة جزئية محافظة (طول ≥ 5) عند الحاجة.
   - إن لم يوجد: «غير مدرج» + `insufficient`.
   - إن وُجد: تحديد الحالة (حظر/شرط/تقيد/حفظ/UV/وسم).
   - فحص الحدود المنطبقة فقط (`leave_on` ثم `product_types`).
   - مقارنة التركيز إن وُجد، وإلا `concentration_unknown`.
4. العدّادات تُحسب من التسميات، والتنبيهات تُرتّب حسب الخطورة.
5. لا يوجد `score` في نوع نتيجة التجميل أصلًا — المنع على مستوى النوع، وليس مجرد قرار واجهة.

## 4. قرارات تقنية

| القرار | السبب |
|---|---|
| React + Vite + TypeScript | تطوير سريع، بناء ثابت، فحص أنواع صارم. |
| HashRouter | يعمل على GitHub Pages والاستضافة الثابتة دون إعادة توجيه. |
| `base: './'` | يعمل في الجذر أو مسار فرعي. |
| JSON مضمّن | لا شبكة، لا خادم، قابلية مراجعة كاملة، وحجم صغير. |
| لا مكتبة UI | تحكم كامل في RTL والهوية، وتقليل التبعيات. |
| لا مكتبة حالة | الحالة محصورة في سياق واحد. |
| خطوط محلية WOFF2 | لا طلبات خارجية، ثبات بصري. |
| تخزين محلي فقط | خصوصية، وعمل دون حساب. |
| استيراد باردكود اختياري | يقلل الإدخال اليدوي دون جعل الشبكة شرطًا. |

## 5. نقاط التوسع

- **إضافة مادة:** أضف كائنًا إلى JSON المطابق + مرجعًا إن لزم، ثم شغّل `npm run validate` و`npm test`. لا حاجة لتعديل المحرك إلا إذا احتجت نوع حد جديدًا.
- **إضافة نوع حد:** وسّع `LimitKind` في `types/index.ts`، ثم أضف منطق التحقق في محرك التجميل وواجهة بطاقة المعرفة.
- **إضافة لغة:** النصوص العربية موزعة في الصفحات والقاعدة. استخراجها إلى ملفات i18n خطوة لاحقة، لكن البنية الحالية لا تفترض لغة في المحركات.
- **إضافة مصدر:** أضف `Reference` وتحقق من الرابط ورقم الوثيقة. لا تضف مرجعًا بلا `accessed`.
- **تحسين الأداء:** الحزمة الحالية نحو 530 كيلوبايت غير مضغوطة. يمكن تقسيم `ReportPage` و`KnowledgeBasePage` عبر `React.lazy` عند الحاجة.

## 6. حدود معمارية مقصودة

- لا قاعدة بيانات علائقية ولا API؛ لذلك لا توجد مشاركة تقارير بين الأجهزة.
- لا مصادقة؛ لذلك لا توجد حماية لتقارير محفوظة على جهاز مشترك.
- لا تحقق خادمي من البيانات المستوردة؛ المسؤولية على المستخدم في مراجعة الحقول.
- لا توجد خدمة تحديث تلقائي للمراجع؛ التحديث يدوي وموثق في `meta.json` و`CHANGELOG.md`.
